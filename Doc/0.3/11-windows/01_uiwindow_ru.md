# UiWindow

Базовый класс окна: подключает дерево элементов фреймворка к обычному окну RimWorld
(`Verse.Window`). Обычно напрямую не создаётся — используйте `ModalWindow` (или его потомков
`MessageWindow`/`ConfirmWindow`, см. соответствующие страницы).

`RimUI.Adapter.UiWindow : Verse.Window`

## Пример

```csharp
var root = new Grid();
root.Cell(12, Button.Make("Привет"));
var window = new UiWindow(root) { FixedSize = new Vector2(400f, 300f) };
window.Show();
```

## Параметры

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `Root` | `UiElement` | из конструктора | Корневой элемент содержимого. |
| `Theme` | `Theme` | `null` | Явная тема окна; `null` = следовать активной теме, меняющейся на лету. |
| `FixedSize` | `Vector2` | `Vector2.zero` | Фиксированный размер; `0` = авто-подгон под контент (ширина до 92% экрана, высота до `Theme.MaxWindowHeightFraction`). |
| `Resizable` | `ResizeEdges` | `None` | За какие края окно тянется мышью. См. раздел «Растягивание окна» ниже. |
| `MinWindowSize` | `Vector2` | `(180, 120)` | Нижняя граница размера при растягивании. |
| `MaxWindowSize` | `Vector2` | `Vector2.zero` | Верхняя граница; `0` по оси = ограничение только экраном. |
| `DragHandle` | `UiElement` | `null` | Элемент, за который окно тащат. `null` = окно не перетаскивается. См. раздел «Перетаскивание окна». |
| `HideContentWhileDragging` | `bool` | `true` | Прятать содержимое, пока окно тащат. |

**Жизнь состояния окна**: внутреннее состояние (скроллы, фокус, раскрытия деревьев, значения
контролов без пользовательского источника) живёт СТРОГО от открытия до закрытия окна. Каждое
открытие — чистая инициализация, даже при повторном `Show()` того же экземпляра. Ничего не
переживает закрытие; сбор данных перед закрытием — задача мододела (колбеки/`OnClose`).

## Точная формула авто-размера

```
maxW = UI.screenWidth * 0.92         // захардкоженный литерал, НЕ настраивается темой
maxH = UI.screenHeight * Theme.MaxWindowHeightFraction   // по умолчанию 0.85

итоговая ширина  = min(содержимое.Width  + 36, maxW)   // 36 = 2×Chrome (поля окна по 18px)
итоговая высота  = min(содержимое.Height + 36, maxH)
```

`maxH` считается от ПОЛНОЙ высоты экрана в пикселях — без вычета высоты нижней панели RimWorld
или других элементов интерфейса игры. Содержимое меряется с доступной шириной `maxW - 36` (то
есть уже с учётом полей окна). Если после этих ограничений контент по высоте всё равно не влезает
в получившееся окно — включается внутренний скролл (порог `содержимое.Height > доступная_высота
+ 0.5`, эпсилон на погрешность float).

## Растягивание окна

```csharp
new ModalWindow(body)
{
    Title = "Отчёт",
    Resizable = ResizeEdges.All,
    MinWindowSize = new Vector2(260f, 160f),
}.Show();
```

Значения `ResizeEdges` — те же, что у блоков (`All`, `Horizontal`, `Corners`, отдельные стороны
и углы); полный список — на странице «Style — модель стиля».

Особенности именно окон:

* **тяга за левый и верхний края двигает и позицию** — противоположная сторона остаётся на
  месте, окно не «уползает»;
* **вытянутый размер запоминается** и отдаётся вместо расчётного: у окна с авто-подгоном размер
  считается по содержимому каждый раз, когда игра его спрашивает (открытие, смена разрешения,
  UI-масштаба), и без этого окно прыгало бы обратно;
* зона захвата лежит **на видимой рамке окна** — той, которую рисует панель, а не на границе
  системного прямоугольника: когда панель рисует фреймворк, нативная подложка выключена и рамка
  ложится внутрь полей. Ширина зоны — 3 точки наружу и 6 внутрь; оба числа переопределяются
  (`ResizeGrabOut`, `ResizeGrab`).

## Увод окна за край экрана

Окно можно утащить за край: за левый, правый и нижний уходит до **80%** его размера, на экране
остаётся пятая часть. За **верхний край окно не уходит совсем** — за шапку его тащат, и уведя её,
вернуть окно было бы нечем.

Доля настраивается переопределением `OffscreenFraction`.

Зажатие пересчитывается не только при перетаскивании, но и при **смене разрешения экрана или
UI-масштаба**: уведённое окно иначе могло бы остаться целиком за границей.

## Перетаскивание окна

Окно тащат за **зону захвата** — любой элемент содержимого, обычно шапку:

```csharp
var header = new FlexBox(Axis.Row) { Style = { Cursor = CursorKind.Move } };
header.Add(new Text("Производственная консоль"));

var win = new UiWindow(root);
win.SetDragHandle(header);        // за этот элемент окно и тащат
```

Дальше нужен один вызов из отрисовки содержимого — **после** того, как зона захвата нарисована:

```csharp
public override void DoWindowContents(Rect inRect)
{
    // ... раскладка и отрисовка содержимого, включая зону захвата ...
    HandleWindowDrag();
}
```

Порядок здесь не формальность: к этому моменту кнопки внутри зоны уже разобрали нажатие, и окно
видит, свободно ли оно. Иначе нажатие на «закрыть» тащило бы окно вместе с нажатием.

Зона захвата берётся по её границам после раскладки, поэтому до первого кадра перетаскивания нет.

`ModalWindow` всё это делает сам: у него зона захвата — шапка, включается флагом `Draggable`.

**Перетаскивание средствами Verse (`Window.draggable`) при этом отключают.** Оно тащит окно из
любой точки и перехватывает клики содержимого.

### Содержимое на время перетаскивания

Окно двигается столько раз, сколько раз перерисовывается, поэтому тяжёлое окно при перетаскивании
отстаёт от курсора ровно на время своей отрисовки. Поэтому на это время содержимое **не
раскладывается и не рисуется** — остаётся только панель окна. Считать и рисовать нечего, и кадр
короткий независимо от того, что внутри.

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `HideContentWhileDragging` | `bool` | `true` | Прятать содержимое, пока окно тащат. |

Выключают у окна, которое заведомо дёшево в отрисовке и должно оставаться читаемым:

```csharp
win.SetHideContentWhileDragging(false);
```

**Цена:** пока содержимое не рисуется, его не существует и для игрового слоя ввода — курсор ввода
из поля при перетаскивании слетает. Сами поля и их текст возвращаются, фокус — нет.

## Наведение и окно сверху

Пока над окном находится другое, его содержимое на курсор не отзывается: ни подсветки, ни
курсоров, ни подсказок. Считается это по верхнему окну под мышью, а не по порядку отрисовки, и
работает само — настраивать нечего.

Растягивание и перетаскивание держатся того же правила: начать их сквозь чужое окно нельзя, но уже
начатое окно доводит до конца, даже если курсор ушёл в сторону. Пока идёт любой захват — окна,
растягиваемого блока, ползунка, перетаскивания содержимого — мышь считается принадлежащей этому
окну, где бы она ни была.

Захват при этом **один на весь фреймворк**: пока одно окно тащат или тянут, второе не начинает ни
того, ни другого.

Окнами дело не ограничивается: всплывающие сообщения игры и её подсказки — тоже окна, и лежат они
поверх любого нашего. Пока такое накрывает элемент, наведение на нём не работает: нажатие ушло бы
им, а не нам.

## Стили

Панель окна — `Theme.WindowPanelFor(SheetKey)` (`protected virtual string SheetKey => "window"`,
переопределяется наследниками).

## Методы

| Метод | Возвращает | Описание |
|---|---|---|
| `UiWindow(UiElement root, Theme theme = null)` (конструктор) | — | Создать окно с корневым элементом. |
| `Show()` | `void` | Добавить окно в `Find.WindowStack`. |
| `SetDragHandle(UiElement)` | `void` | Назначить зону захвата для перетаскивания. |
| `HandleWindowDrag()` (protected) | `void` | Разобрать нажатие на зоне захвата. Зовётся из отрисовки содержимого ПОСЛЕ неё. |
| `InitialSize` (override, свойство) | `Vector2` | Авто-размер по контенту либо `FixedSize`. |

## События

Собственных `Action`-колбэков нет — жизненный цикл управляется методами `Verse.Window`
(`PreOpen`, `PostClose` и т.п.), переопределяемыми в `ModalWindow` (см. страницу «ModalWindow»,
поле `OnClose`).

## Поддержка механик

| Механика | Поддержка | Пояснение |
|---|---|---|
| Стиль панели | Да | `Theme.WindowPanelFor(SheetKey)`. |
| Спрайт-рамка | Да | Если задан спрайт панели — гасится нативная подложка окна (`doWindowBackground=false`). |
| Скролл при переполнении | Да | Встроенный собственный `ScrollBox`, не нативный `Widgets.BeginScrollView`. |
| Состояние между открытиями | Нет | Намеренно: каждое открытие — с чистого листа; данные собирает мододел. |
| Disabled/Hover-fade | Не применимо | Понятия относятся к отдельным элементам внутри окна, не к окну целиком. |
